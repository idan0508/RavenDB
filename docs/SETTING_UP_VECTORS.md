# Setting Up Embeddings and Vector Search (Final Workflow)

To make the AI Agent genuinely intelligent, it must be able to perform "**Semantic Search**". Unlike normal search (which looks for exact words), Semantic Search looks for the *meaning* of words using **Vectors** (arrays of numbers representing text).

This guide is the updated, final workflow after the March 18 fixes.
It covers cleanup, regeneration, and validation for vector quality in RavenDB.

---

## 1. Why We Updated This

We identified that some old vectors were generated with incorrect model/task settings.
That can silently degrade retrieval quality even when documents exist.

So the correct strategy is:
- clean invalid vector outputs,
- regenerate with embedding-specific tasks,
- verify index and agent read the correct vectors.

---

## 2. Collection and Field Conventions

Use the correct source fields for each collection.

Recommended:
- Documentation collection: embed `SearchableContent`.
- Discussions collection: embed `Body` and optionally `Title`.
- Google Groups collection: embed cleaned text body and optionally title.

Why `SearchableContent` for docs:
- It is already normalized for retrieval (title + sections + content).
- It avoids noise and reduces inconsistent chunk semantics.

---

## 3. Reset Strategy (If Old Vectors Are Polluted)

1. In RavenDB Studio, inspect existing embedding output collections/tasks.
2. Delete embedding outputs generated by wrong model/task config.
3. Keep source collections (documents) intact.
4. Recreate embedding generation tasks with corrected source paths.
5. Rebuild or wait for dependent indexes to catch updated vectors.

Important:
- Do not delete core source collections unless absolutely necessary.

---

## 4. Create Embeddings Tasks

### Task A: Documentation
- Task Name: `embed-docs`
- Source Collection: `Documentation_Sitemaps` (or your active docs collection)
- Connection String: your embeddings connection (Ollama/OpenAI/Azure)
- Source Path: `SearchableContent`
- Chunking: plain text paragraphs (or provider default if already chunk-safe)

### Task B: Discussions
- Task Name: `embed-discussions`
- Source Collection: `Discussions`
- Source Paths: `Body`, `Title`

### Task C: Google Groups
- Task Name: `embed-google-groups`
- Source Collection: `GoogleGroupMessages`
- Source Paths: cleaned message body, `Title`

---

## 5. Validation Checklist

After task creation and execution:

1. Verify vectors exist on recent documents in each source collection.
2. Verify no stale vectors remain from deprecated tasks.
3. Run semantic queries on each domain and check relevance.
4. Confirm your multi-map semantic index reads the new vector fields.
5. Test agent answers against known benchmark questions.

---

## 6. Operational Sequence (Recommended)

1. Finish docs ingestion rerun:

```powershell
.\.venv\Scripts\python.exe .\scripts\collect_docs_sitemap.py --all-versions --workers 20 --collection "Documentation_Sitemaps"
```

2. Review failed URLs and failure reasons.
3. Run embeddings tasks.
4. Validate retrieval quality in Studio queries and agent responses.

---

## 7. Common Failure Modes

### Wrong collection name
Cause:
- semantic ID prefix and requested collection name mismatch.

Effect:
- documents appear in unexpected collection.

### Wrong source path for embedding
Cause:
- embedding task points to noisy or empty field.

Effect:
- weak or irrelevant search results.

### Mixed old/new vectors
Cause:
- old vectors not cleaned before new task run.

Effect:
- inconsistent retrieval quality.

---

## 8. Final Recommendation

For final project stability:
- Keep source docs in place.
- Rerun ingestion incrementally first.
- Regenerate embeddings from clean source paths.
- Validate with a fixed QA benchmark set before presentation.
